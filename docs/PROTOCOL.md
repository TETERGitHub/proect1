# Licence protocol, key format, payload cipher and loader state machine

This document describes what the code **does today** (v0, unversioned), what it protects against, and what it does not.
Nothing here was exercised against a real executor, TLS or a tunnel; the Luau side runs on the Luau CLI against the real
Python server over localhost HTTP (`server/tests/test_integration.py`). All keys in tests are dummy keys made with a
throw-away secret.

## 1. Secrets and what each is for

| Secret / value | Lives in | Used for | Never used for |
|---|---|---|---|
| Licence signing secret (32 bytes, `.license/secret.hex`) | the server and the machine that runs `keygen.py`; **also embedded in `MM2Hub.lua` if you build the offline variant (`--license`)** | HMAC over the key body (`MAC_BYTES = 10` of the digest) so keys cannot be forged | encrypting payloads |
| Licence key (`MM2H-...`) | the customer; stored in plain text in the executor workspace `MM2Hub/license.key` after the first success | proves the right to download the hub **and** is the symmetric secret the payload is encrypted to | - |
| Per-response nonce (12 random bytes) | generated by the server for each activation (`os.urandom(12)`) | makes `k` unique per response | - |
| Payload key `k` | derived on both sides, never transmitted | keystream seed **and** HMAC key (see weaknesses) | - |

The key is therefore both a credential and a secret key. Anyone who can read the key file or see the key can decrypt any
response captured for it. That is inherent to this design (the client must be able to decrypt) and is why the server can
only raise the cost of leaking the hub, not prevent it.

## 2. Key format

`MM2H-` + Crockford base32 (groups of 5) of 24 bytes: `version(1) mode(1) issued(4, BE) value(4, BE) nonce(4) mac(10)`.
`mode 0`: `value` is an absolute expiry (unix seconds). `mode 1`: `value` is a duration counted from the first activation.
`mac = HMAC-SHA256(secret, first 14 bytes)[:10]` (80 bits). The 4-byte nonce identifies the key for revocation.
Decoding is strict: exact length, zero padding bits, one canonical spelling (case, `-`, spaces, `O->0`, `I/L->1` are
accepted on input and normalised).

## 3. Wire messages (JSON over HTTPS, `Content-Type: application/json`)

| Request | Success `200` | Refusal |
|---|---|---|
| `POST /v1/activate` `{key, uid}` | `{ok:true, expires, now, nonce, tag, payload}` (`nonce` base64 of 12 bytes, `tag` 32 hex chars, `payload` base64) | `403 {ok:false, error}` |
| `POST /v1/ping` `{key, uid}` | `{ok:true, expires, now}` | `403 {ok:false, error}` |
| any | - | `400 bad request`, `413 bad request size` (>4096 B), `404 not found`, `429 too many attempts, wait a minute` |

`uid` must be an integer (a boolean is rejected). A missing `uid` is refused with `account id required` when account
binding is on. Error strings are the only machine-readable reason; the loader maps them to Russian
(`core/LicenseText`). **There is no error code field and no protocol version field** (open item 1).

Server rules (`server/licensing.py`): signature must verify; nonce not in the revocation list; `issued` not more than 2
days in the future; first uid binds the key; expiry compared against the server clock; first activation time stored for
`mode 1`. The rate limiter keys on the TCP peer, or on `CF-Connecting-IP` / the last `X-Forwarded-For` entry **only when
the peer is loopback** (the local tunnel or reverse proxy); it forgets idle addresses beyond 10 000 entries.

## 4. Payload cipher (`core/PayloadCipher`, `server/licensing.py`)

```
k          = SHA256("MM2HUB-PAYLOAD" || canonicalKey || nonce)
keystream  = SHA256(k || u32be(counter)) for counter = 0,1,2,...   (32 bytes per block)
cipher     = plaintext XOR keystream
tag        = first 16 bytes (32 hex) of HMAC-SHA256(k, nonce || cipher)
```

Receiving order (client): structural key check -> `activate` -> field types -> base64 decode (strict) -> nonce length 12
-> **tag compared (constant-time on equal-length hex) before any decryption** -> decrypt -> compile -> run.
Corrupted ciphertext, a wrong nonce, a wrong key, a truncated payload, a missing or non-hex tag and wrongly typed
arguments all end in `nil, "payload authentication failed ..."`; none throw (`tests/t_audit.luau`).

### Known weaknesses (not fixed: they change the wire format)

1. No version byte and no negotiation, so the format cannot evolve without breaking old loaders.
2. One key `k` is used both as keystream seed and as HMAC key (no domain separation). No practical attack is known for
   this exact layout, but it is not the construction a reviewer would sign off; HKDF-style separate subkeys are cleaner.
3. The tag covers `nonce || cipher` only. **`expires` and `now` in the same response are not authenticated.** Over TLS this
   needs a network attacker who defeats TLS; without TLS they can be rewritten to lengthen the local term until the next
   ping. A rewritten payload or nonce is still detected.
4. 128-bit truncated tag, 80-bit key MAC: adequate against online guessing behind the rate limiter, not a margin to rely on.
5. Replay: a recorded activation response for a key stays decryptable and valid forever (no freshness binding). It yields
   nothing the key holder does not already have, but it also means a revoked key's old response still decrypts.
6. Confidentiality depends on the server never repeating a nonce (random 96-bit: fine in practice).
7. Self-made construction: use a reviewed AEAD (e.g. XChaCha20-Poly1305 / AES-GCM) if a real library is ever available in
   the executor. Pure-Luau SHA-256 costs about 1.3 s for the 640 KB hub on a desktop (slower on phones).

### Versioned migration plan (not implemented)

* Loader sends `"proto": 2` in the request. Old loaders do not, so the server answers them exactly as today.
* v2 answer adds `"v": 2`, derives `kEnc = HMAC(k, "enc")`, `kMac = HMAC(k, "mac")`, and the tag covers
  `v || expires || now || nonce || cipher`.
* The v2 loader requires `v == 2` and rejects a v1 answer to a v2 request (downgrade check).
* Ship loader first with v1 fallback allowed, switch the server default, then drop v1 after the last v1 loader is gone.
* Add an `error_code` field alongside `error` at the same time so clients stop matching English strings.

## 5. Loader state machine (`loader/Loader.luau`)

States: `idle` -> (`readKey` stored) or (`prompt`) -> `activating` (busy) -> `running` | `idle` + prompt with the error ->
`stopped`. Transitions and guards:

| Event | Guard | Result |
|---|---|---|
| submit key | `busy`, `running` or `stopped` | ignored (`already running`) |
| submit key | free | `busy = true`; any outcome sets `busy = false` |
| activate refused or failed | - | `lastError` set, new prompt shows the message |
| hub chunk raises | - | `hub failed to start: ...`, no heartbeat started, prompt again, retry allowed |
| hub started | - | key written, exactly one heartbeat spawned |
| ping `ok:false` with a **fatal** message (revoked, expired, invalid key, bound to another account, not valid yet) | - | `stop()`: unload, notify |
| ping `ok:false` with any other message (429, bad request, unknown) | - | logged, ignored |
| ping transport failure / unreadable answer | - | `pingFailures += 1`, logged; reset by the next answer; hub keeps running |
| local term end (`serverNow + elapsed >= expires`) | numeric fields only | `stop("Your key has expired.")` |
| `stop()` | already stopped | no-op (idempotent); `unload` and `notify` errors are caught |

Offline behaviour: an expired term always stops the hub (local clock). A **revocation cannot be noticed while the server
is unreachable**; the loader tolerates this by design so an outage does not kill paying users. `deps.maxPingFailures`
(optional, default off) stops the hub after that many consecutive failed pings if you prefer the opposite policy.
Closing the key window without submitting simply leaves nothing running. The loader holds no connections or UI of its
own after the window is destroyed.

Open contract questions (the server API does not define them, so they were not invented): an `error_code` field; whether
`429` should carry `Retry-After`; whether a ping may extend `expires`.
