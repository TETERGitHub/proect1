# Licence keys

## Generating keys

```bash
python3 tools/keygen.py init                         # once: creates .license/secret.hex (keep it private, back it up)
python3 tools/keygen.py gen --duration "1mo 15d 12h" # key valid for 1 month 15 days 12 hours counted from now
python3 tools/keygen.py gen --years 1 --months 2 --days 3 --hours 4 --minutes 5 --seconds 6
python3 tools/keygen.py gen -i                       # interactive: asks month, year, day, hour, minute, second
python3 tools/keygen.py gen --duration 30d --mode activation   # 30 days counted from the buyer's first activation
python3 tools/keygen.py gen --duration 7d --count 20 --note "giveaway"
python3 tools/keygen.py info MM2H-XXXXX-...          # decode and verify a key
python3 tools/keygen.py list                         # log of issued keys (.license/issued.csv)
```

Duration tokens: `y`, `mo`, `w`, `d`, `h`, `m`, `s` (long forms like `months`, `minutes` also work).
In *absolute* mode months and years are calendar-aware. In *activation* mode they are approximated (month = 30 days, year = 365 days) because the start date is unknown when the key is made.

Build with the key check: `python3 tools/build.py --license` (embeds the secret and requires a key at start).
Without `--license` the hub runs without a key.

## What the key check protects - and what it does not

Keys are `HMAC-SHA256`-signed and contain their own expiry. Verified by automated tests (`tests/t_license.luau`), with keys generated by the **Python** tool and verified by the **Luau** code:

- changing any single character of a key invalidates it;
- the expiry cannot be edited without the secret;
- the server time of Roblox is used, and a stored high-water mark rejects clocks set back;
- keys can be revoked by id (`License.setRevoked`).

**It is not tamper-proof.** The verifier and its secret must ship inside the script, so:

1. anyone who can read the script can extract the secret and generate keys;
2. anyone can patch the check out of the code.

This cannot be fixed inside a client-side script. The only robust approach is the server-authoritative loader described in `docs/SERVER.md`, where the real hub code is delivered only after your server accepts the key. Even then, a determined person with a valid key can dump the code from memory; the goal is to raise the cost, not to reach 100 %.
